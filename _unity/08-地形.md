地形有两条创建路径。

- Unity 内置 Terrain 把高度、贴图混合、草、树、LOD 和碰撞包在一起
- 自定义地形只保存自己的 `float[,]`，再用 Mesh 画出来

## Terrain 和 TerrainData

场景里的 Terrain 组件负责画和做碰撞。真正的数据在 TerrainData 里：

- `heightmapResolution`：高度图边长，必须是 `2^n + 1`，例如 129、257、513
- `size`：地形在世界里的长、高、宽。`size.y` 是高度 1 对应的世界高度
- `terrainLayers` / alphamap：多层贴图怎么混
- `treePrototypes` / `treeInstances`：树
- `detailPrototypes` / detail layer：草

`TerrainCollider.terrainData` 必须和 `Terrain.terrainData` 指向同一份，射线和物理才打得中这块地形。

## 高度图

高度图不是网格顶点。它是一张采样图，渲染时 Unity 再按 LOD（Level of Detail）决定用多少三角形。

读出来的值在 0~1 之间，乘上 `size.y` 才是世界高度。数组下标是 `[z, x]`。

```csharp
int _resolution = mTerrainData.heightmapResolution;
float[,] _heights = mTerrainData.GetHeights(_xBase, _zBase, _width, _height);
_heights[_z, _x] = Mathf.Clamp01(_heights[_z, _x] + _deltaHeight / mTerrainData.size.y);
mTerrainData.SetHeightsDelayLOD(_xBase, _zBase, _heights);
mTerrainData.SyncHeightmap();
```

`SetHeightsDelayLOD` 先改采样，不立刻重算整块 LOD。`SyncHeightmap` 再更新显示和 `TerrainCollider`。笔刷只改命中点周围的一小块，所以传的是局部窗口，不是整张图。

世界坐标换到高度图下标：

```csharp
Vector3 _local = transform.InverseTransformPoint(_worldPoint);
int _x = Mathf.RoundToInt((_local.x / mTerrainData.size.x) * (_resolution - 1));
int _z = Mathf.RoundToInt((_local.z / mTerrainData.size.z) * (_resolution - 1));
```

## 混合图层

每一层是一个 TerrainLayer，上面有漫反射贴图和平铺尺寸。混合权重在 alphamap 里，下标是 `[z, x, layer]`，同一个像素上各层加起来是 1。

```csharp
TerrainLayer _layerA = new TerrainLayer();
_layerA.diffuseTexture = mLayerTextureA;
_layerA.tileSize = new Vector2(4f, 4f);
mTerrainData.terrainLayers = new TerrainLayer[] { _layerA, _layerB };

float[,,] _maps = new float[_height, _width, 2];
_maps[_z, _x, 0] = 1f - _blend;
_maps[_z, _x, 1] = _blend;
mTerrainData.SetAlphamaps(0, 0, _maps);
```

第一层可以是木头，第二层是水面，边缘保持木头、中心按权重混成水。HDRP 用 `DefaultHDTerrainMaterial`，并打开 `drawInstanced`。

## 自定义高度图

内置高度图被限制在 0~1。自定义地形的高度直接是世界单位，存在 `float[,]` 里。

- 格子：`1000 x 1000`
- 顶点：`1001 x 1001`，因为每条边上的格子要共享顶点
- 下标：`mHeights[z, x]`
- 格子边长：`0.05`。世界尺寸是 `50 x 50`，顶点数量仍然是一百万这一级

`Raise` 按格子半径做圆形衰减，中心加满，边缘加 0，并返回被改过的顶点范围。

## 程序化网格

一块完整的 1000x1000 格子有 1,002,001 个顶点，超过 16 位索引的 65535。不把它们塞进同一个 Mesh，而是切成 `100 x 100` 格子一块：

- 每块顶点 `101 x 101 = 10201`，用 16 位索引就够
- 顶点位置：`(x * cellSize, height, z * cellSize)`
- 每个格子 2 个三角形、6 个下标
- UV 按整张地形铺开，从 `(0, 0)` 到 `(1, 1)`
- 法线由左右、前后四个高度差算出来，分块接缝不会因为各自 `RecalculateNormals` 而裂开
- 某块顶点一旦超过 65535，这块改用 `IndexFormat.UInt32`

## 刷高度和 MeshCollider

用 `Camera.ScreenPointToRay` 打到自己的 `MeshCollider` 上，把命中点换算成最近的顶点，再调用 `Raise`。然后只刷新碰到的那几块：

1. 改这几块缓存里的顶点 Y 和法线
2. 写回 `mesh.vertices` / `mesh.normals`
3. `RecalculateBounds`，否则包围盒还是平的，块会被错误剔除
4. `MeshCollider.sharedMesh` 先设成 null 再设回同一块网格。只改顶点不会让旧碰撞体更新

非凸 `MeshCollider` 不能挂 `Rigidbody`，地形是静止碰撞体。点一下先抬一段高度，按住则持续抬。

## 二进制地形数据

读写拆成两层：`SaveToFile` / `LoadFromFile` 管文件，`Export` / `Import` 管流里的字段顺序。文件在 `Application.persistentDataPath` 下，名字是场景名加 `.height`，默认 `GameScene.height`。目录字符串末尾要带分隔符，因为文件名是直接拼出来的：`_path + sceneName + ".height"`。

`Import` 必须按约定顺序读。版本号留给以后改格式。高度数量和当前顶点网格对不上时，`Import` 抛异常，`LoadFromFile` 的 `catch` 会调用 `Free()` 把内存里的高度清成 0。文件根本不存在时不调用 `Free()`，已经刷过的高度还在。

保存后重新加载要 `RefreshAll`，每一块的网格和 `MeshCollider` 一起更新。旧的字段布局对不上这套顺序时不能再读。

## 简答

**Unity Terrain 和程序化 Mesh 地形的优缺点？**

- 内置 Terrain 适合大面积高低起伏的地面。高度图和渲染网格是分开的，远处自动 LOD；多层贴图、草、树、洞和地形碰撞都有现成数据。笔刷改的是采样，不是逐个三角形。限制也在这里：高度必须是规则网格上的一个数，做不了洞穴、悬空和垂直内凹；高度被压进 `0~1`，精度由 `heightmapResolution` 和 `size.y` 决定；材质、草树都要走它的格式。
- 程序化 Mesh 的顶点、下标、UV 都自己写，数据格式也自己定，可以直接把 `float[,]` 存成二进制。它能做悬空、破洞和不规则边界，也能当成普通网格参与别的流程。代价是 LOD、分块缝合、多层贴图、草和树都要自己做。顶点数就是绘制和碰撞的开销，没有 Terrain 那种“采样很多、三角形可以很少”的缓冲。

**为什么自定义 Mesh 不能使用过多顶点？怎么优化大型地形？**

每个顶点至少带位置、法线和 UV。1000x1000 个格子大约是 100 万顶点、200 万三角形。这些数据要留在内存里，改高度时还要上传到 GPU。16 位索引最多 65535 个顶点，再大就必须换成 32 位下标，下标数组也跟着变大。

碰撞更明显。非凸 `MeshCollider` 要按三角形烹饪。一整张 200 万三角形的网格，点一下就重新烹饪一次，帧时间会直接卡住。一块巨大网格的包围盒也大，剔除变成全画或者全不画。

大型地形按块拆开：

- 逻辑仍是一整张 `float[,]`，渲染和碰撞按 `100 x 100` 格子分块
- 每块顶点控制在 65535 以内，继续用 16 位索引
- 笔刷只刷新碰到的块，碰撞也只重新指定那几块的 `sharedMesh`
- 远处可以用更稀的格子采样同一张高度图，做 LOD
- 碰撞可以用更稀的网格，或者只给角色附近的块挂 `MeshCollider`
- 草和树不要写进地形三角形，单独做实例化
