## 坐标系
### 一、五大坐标系
1. 全局坐标系
- 全局坐标系适用于描述场景内所有物体位置的方向的基准，也称为世界坐标系
- unity中创建的物体都是以全局坐标系中的坐标原地(0, 0 , 0)，来确定各自的位置的
- 使用transform.position来获取游戏对象的世界坐标
2. 局部坐标系
- 局部坐标系也成为模型坐标系或物体坐标系。每个物体都有自身独立的物体坐标系
- 当物体移动或改变方向时，和这个物体相关的坐标系也随之改变
- 模型mesh保存的顶点坐标均为局部坐标系下的坐标
3. 本地坐标系transfrom.localPosition
- 可以获取物体在父物体的局部坐标系中的位置点
- 父子关系，子物体以父物体的坐标点为自身坐标的原点
- 如果没有父物体，那么transform.localPositon以这个物体在的全局坐标系中的坐标为基准
4. 屏幕坐标Screen Space
- 屏幕坐标系是在屏幕上的二维坐标系为基准。以像素来定义，屏幕的左下角为(0, 0)，右上角为(Screen.width, Screen.height)，z轴的坐标是摄像机的世界坐标的z的坐标的负值
- 鼠标位置坐标属于屏幕坐标，通过Input.mousePosition获取
- 手指触摸屏幕属于屏幕坐标，通过Input.GetTouch(0).position来获取单个手指触摸屏幕时的手指坐标
5. 视口坐标系
- 视口坐标系是将Game视图的屏幕坐标系单位化，左下角(0, 0),右上角(1, 1)
- z轴坐标是摄像机的世界坐标中的z轴的负值

### 二、坐标变换
#### 1. 指向
- Transform.forward: 当前物体的物理坐标系z轴在世界坐标系上的指向
- Transform.right: 当前物体的物理坐标系x轴在世界坐标系上的指向
- Transform.up: 当前物体的物理坐标系y轴在世界坐标系上的指向
#### 2. 缩写
- Vector3.forward(0, 0, 1)。在transform.Translate()中使用时，如果不表面坐标系，则为物体的局部坐标，即物体自身的正前方
- Vector3.right(1, 0, 0)
- Vector3.forward(0, 1, 0)
#### 3. 转化
3.1 将一个坐标点从局部坐标系转换到全局坐标系
- Transform.TransformPoint(Vector3 position)

3.2 将一个坐标点从全局坐标系转换到局部坐标系
- Transform.InverseTransformPoint(Vector3 position)
- 父物体调用 `InverseTransformPoint(子物体.position)`，得到的就是子物体的 `localPosition`。没有父物体时，`localPosition` 和 `position` 相同

```csharp
Vector3 _world = mTarget.position;
Vector3 _local = mTarget.localPosition;
Vector3 _worldFromLocal = mTarget.TransformPoint(Vector3.zero);
```

3.3 将一个方向从局部坐标转换到全局坐标系
- Transform.TransformDirection(Vector3 diretion)

3.4 将一个方向从全局坐标系转换到局部坐标系
- Transform.InverseTransformDirection(Vector3 diretion)

3.5 将一个向量从局部坐标系转换到全局坐标系
- Transform.TransformVector(Vector3 vector)

3.6 将一个向量从局部坐标系转换到全局坐标系
- Transform.InverseTransformVector(Vector3 vector)

3.7 屏幕坐标系和全局坐标系的转换

`Camera.main` 是带 `MainCamera` 标签的那台摄像机。

```csharp
Camera.ScreenToWorldPoint(Vector3 position) // 将屏幕坐标转换成全局坐标系
Camera.WorldToScreenPoint(Vector3 position) // 将全局坐标转换成屏幕坐标
Input.mousePosition // 获取鼠标在屏幕坐标系中的坐标

Vector3 _screen = Camera.main.WorldToScreenPoint(_world);
```

- `WorldToScreenPoint`：变成屏幕像素，原点在画面左下角。返回值的 x、y 是像素，z 不是像素，而是该点在摄像机前方的距离。点在摄像机背后时 z 为负
- `ScreenToWorldPoint`：把像素变回世界坐标。传入的 z 同样是摄像机前方的距离，不是世界坐标的 z。z 写成 0 会得到贴在摄像机近处的一个点

屏幕上只有像素、需要得到世界坐标时用 `ScreenToWorldPoint`。例如战棋或建造游戏里，玩家用鼠标在地面上点一下来放建筑：鼠标位置只有 x、y，把 z 设成摄像机到地面的距离，得到地面上的世界坐标，再在那里生成建筑。直接把 `Input.mousePosition` 传进去时 z 为 0，点会落在摄像机自己附近。

3.8 屏幕坐标系与视口坐标系转换
```Csharp
Camera.ScreenToViewportPoint(Vector3 position) // 屏幕坐标转换成视口坐标
Camera.ViewportToScreenPoint(Vector3 position) // 视口坐标转换成屏幕坐标
```

3.9 全局坐标系和视口坐标系的转换
```Csharp
Camera.WorldToViewportPoint(Vector3 position) // 将全局坐标转换成视口坐标
Camera.ViewportToWorldPoint(Vector3 position) // 将视口坐标转换成全局坐标
```

## 点乘、叉乘
1. 点乘描述了两个向量的相似度，结果越大越相似，还可以表示投影
2. 叉乘得到的向量垂直与原来两个向量
3. 标准化向量：用在只关心方向，不关心大小的时候

### 一、点乘
1. 在unity中是Vector3.Dot函数
2. 点乘是两个向量之间的点积，结果是一个标量(没有方向的量)
```A · B = |A| * |B| * cos(α)```
3. 点乘的意义
- 判断两个向量的夹角：如果点乘结果为正，则夹角小于90度；如果为负数，夹角大于90度；为0，则两个向量夹角为90度
- 计算一个向量在另一个向量方向上的投影长度
- 在物理上，点乘用于计算力在特定方向上的分量，或者判断两个物体之间的相对位置

### 二、叉乘
1. 在unity中用Vector3.Cross函数
2. 叉乘是两个向量的叉积，其结果是一个新的向量，与原来两个向量都垂直。
```A x B = |A| * |B| * sin(α) * n```
- 其中n是一个与A和B都垂直的单位向量，其方向遵循右手定则
3. 叉乘的意义
- 生成一个与两个向量都垂直的新向量
- 在物理中，叉乘用于计算旋转轴或者扭矩
- 图形学中，用于计算表面法线或者确定三角形朝向

### 三、归一化(Normalization)
1. Vector3.normalized
2. 归一化是将一个向量转换成单位向量的过程
3. 在物理和图形学中，归一化通常用于表示物体方向(如光照和反射等)

## 碰撞体

碰撞体用来定义游戏对象的物理碰撞形状。

### 三种常用 Collider

1. **BoxCollider**
   - 盒子，`center` + `size`。变到世界空间后做包围盒重叠测试
2. **SphereCollider**
   - 球，`center` + `radius`。两球心距离小于半径之和就是相交
3. **MeshCollider**
   - 用网格本身。`convex = false` 时按三角形检测；`convex = true` 时先做成凸包再检测
   - `convex = true` 会把网格收成凸包：凹陷、洞会被填上。立方体本身就是凸的，凸包和原来的盒子几乎一样。凹网格如果打开 convex，碰撞范围会大于看得见的模型
   - 非凸 `MeshCollider` 不能勾 `isTrigger`，也不能挂在会动的刚体上。要做触发器，必须先 `convex = true`

`convex` 的两种线框：

- **true**：线框是凸包，凹陷被填平；可以挂 `Rigidbody`；可以当触发器。顶点很多时凸包最多保留约 255 个点
- **false**：线框贴着原始三角形，凹形还在；不能挂 `Rigidbody`，物体因此不会被物理推动；不能当触发器。适合静止复杂网格，开销更大

### IsTrigger 和碰撞事件

`isTrigger = false`：物体互相挡住，回调是 `OnCollisionEnter` / `OnCollisionExit`。

`isTrigger = true`：物体穿过去，不产生碰撞力，回调是 `OnTriggerEnter` / `OnTriggerExit`。

触发器要真正被调用，还要满足：

- 双方至少有一个 Collider 的 `isTrigger` 为真
- 双方至少有一个带 `Rigidbody`
- 网格碰撞体已经 `convex = true`

### 点击拾取

鼠标左键在 Game 窗口里点击时，从相机发出一条射线，打中第一个碰撞体：

```csharp
Ray _ray = Camera.main.ScreenPointToRay(Input.mousePosition);
RaycastHit _hit;
if (Physics.Raycast(_ray, out _hit))
{
    // _hit.collider.gameObject.name
    // _hit.point     命中点
    // _hit.normal    表面法线
    // _hit.distance  射线长度
    // _hit.collider  命中的 Collider 组件
}
```

`ScreenPointToRay` 把屏幕像素变成从相机发出的一条射线。`Physics.Raycast` 沿这条射线找第一个碰撞体，结果放进 `RaycastHit`。Project Settings 里 `Queries Hit Triggers` 打开时，触发器也能被射线打中。

命中后可以直接改渲染颜色：

```csharp
mMeshRenderer.material.color = Random.ColorHSV();
```

### 不走 Physics 的重叠判断

三种检测可以自己算，不调用 `Physics.Overlap`。

- **盒体包围盒**：两个盒子在 X、Y、Z 上的间距，都不大于两边半长之和，才算重叠
- **球体相交**：两球心距离小于等于半径之和
- **球体和盒体**：把球心钳制到盒子范围内，得到盒子上最近点，距离不超过半径就算重叠

## 射线检测
### 射线检测发
1. 原理：从观察点(如摄像机或玩家角色)向目标物体发射射线，若射线达到命中其他物体，则目标被遮挡

```Csharp
private float getDistance(Camera mainCamera, GameObject target) {
    Vector3 origin = mainCamera.transform.position;
    Vector3 targetPos = target.transform.position;
    Vector3 direction = (targetPos - origin).normalized;
    float distance = Vector3.Distance(origin, targetPos)
}

// 被遮挡
if (Physics.Raycast(origin, direction, out RaycastHit hit, distance)) {
    if (hit.collider.gameObject != target) {
        return true;
    }
}
```

### 渲染器回调
1. 原理：利用unity内置的回调函数OnBecameVisible()和OnBecameInvisible()自动触发物体进入/离开摄像机视野事件
2. 局限性：仅判断物体是否在摄像机视锥体内，无法判断是否被遮挡(如在墙后的物体任然出发OnBecameVisible)

### 小球运动速度太快击穿墙壁，解决方案
1. 调整碰撞检测模式：为小球的rigidbody组件这是更高精度的碰撞检测模式
    - 连续碰撞检测(Continuous)：适用于中高速物体，但性能开销中等

    ```GetComponent<Rigidbody>().collisionMode = CollisionDetectionMode.Continuous;```
    - 连续动态碰撞检测(Continuous Dynamic)：针对高速运动物体(如子弹)，精度最高但性能消耗最大

    ```GetComponent<Rigidbody>().collisionMode=CollisionDetectionMode.ContinuousDynamic;```

    - 原理是默认的离散检测(Discrete)按固定时间步长采用位置，高速物体可能跳过碰撞体；连续模式通过插值预测路径，避免漏检

2. 提高物理更新频率

    - 减小Fixed Timestep值，增加物理模拟频率：修改项目设置：Edit > Project Settings > Time > Fixed Timestep(默认是0.02秒，改为0.01秒或者更低)
    - 动态调整：
    ```Csharp
    void Update() {
        Time.fixedDeltaTime = Mathf.Lerp(0.02f, 0.005f, Mathf.InverseLerp(30, 60, Time.frameRate));
    }
    ```

    - 原理：更短的步长意味着单位时间内更多次的碰撞检测

3. 预检测和运动约束
- 射线预检测：在移动前向运动方向发射射线，若前方由墙体则阻止移动

    ```Csharp
    void Move() {
        Vector3 moveDir = transform.forward * speed * Time.deltaTime;
        if (!Physics.Raycast(transform.position, moveDir, moveDir.magnitude, wallLayer)) {
            transform.Translate(moveDir);
        }
    }
    ```

    - 预测物理：计算下一帧位置并提前检测碰撞

    ```CSharp
    void FixedUpdate() {
        Vector3 preditedPos = transform.position + rb.velocity * Time.fixedDeltaTime;
        if (Phycisc.CheckSphere(predictedPos, 0.5f, wallLayer)) {
            rb.velocity *= 0.5f; //提前减速
        }
    }
    ```

4. 优化碰撞体
- 增加墙体厚度
- 使用复合碰撞体：为墙体增添多个重叠的简单碰撞体，增加检测覆盖率
- 简化碰撞体形状：使用Box/Capsule替代Mesh Collider降低计算复杂度
