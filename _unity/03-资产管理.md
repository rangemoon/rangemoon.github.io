xLua 和 Addressables 是不是一套热更？

不是一套。**Addressables / AssetBundle 热的是贴图、Prefab、场景；xLua 热的是逻辑。** 装修三消里两条链共用一份 `version.json`（MD5），下载器是同一套：远程 → persistent 缓存 → StreamingAssets 回退。Lua 打成独立 `lua` 包，不进 Resources，否则脚本打进首包、没法单独更。

**项目里实际做成的是「C# 调 Lua 读数」，不是线上改过 C# 方法。**

启动：`GameStartController.Start` 里先 `LuaHotUpdateManager.PrepareAndStart`，`LuaEnv.AddLoader` 从 lua bundle 取 bytes，`require 'main'` → `require 'game_config'`。业务例如 `LuaGameConfig.GetDailyBonusAmount(day)` 去调 Lua 函数 `get_daily_bonus_amount`。Lua 挂了或包缺失，C# 回退原来的 300/10/2，游戏还能进。

IL2CPP 下 Lua 要碰到的 C# 类型必须 `LuaCallCSharp` / `Generate Code`，否则 stripping 后真机调不到。

#### xLua 怎么「改 C#」，底层是什么

两条路，面试一定要分开说：

| | C# 调 Lua（已落地） | `xlua.hotfix`（只预留入口） |
|---|---|---|
| 做什么 | C# 主动问 Lua 要一个返回值 | 把已经编进包里的某个 C# 方法整段换成 Lua |
| 适合 | 改签到钻石、关卡数值 | 修线上逻辑 bug，不发版 |
| 要不要改 DLL | 不要 | 要。构建时注入桥接代码 |

**底层（hotfix）：**  
Unity 真机多是 IL2CPP：C# → CIL → C++ → 本地码，**运行时不能像编辑器那样随便替换方法体**。xLua 在出包前给打了 `[Hotfix]` 的方法插入一段桥：

```CSharp
进入 C# 方法
  → 查表：这个方法有没有被 Lua 接管
  → 有：把参数交给 Lua 函数，返回值写回
  → 没有：走原来的 C# 实现

/// <summary>
/// 读取加载界面提示。文案由 Lua 按入口开关生成；未就绪时返回空字符串。
/// </summary>
public static string GetLoadingTip()
{
    return LuaHotUpdateManager.CallString("GetLoadingTip", string.Empty);
}
/// <summary>
/// 调用 Lua 全局函数并取字符串。未就绪或失败时返回 fallback。
/// </summary>
public static string CallString(string functionName, string fallback)
{
    object result = Call(functionName);
    if (result == null)
        return fallback;
    string text = result as string;
    return text != null ? text : fallback;
}
```

运行时 `xlua.hotfix(CS.LuaHotfixTarget, "GetPatchStamp", luaFunc)` 就是往这张表里登记。没做 `HOTFIX_ENABLE` + Generate Code + Inject，表永远是空的，调用会失败，所以项目里用 `pcall` 包着，没注入也不崩。我真机没跑通注入，简历只写数值热更。

和 HybridCLR 对比（被问就一句）：HybridCLR 可以热更 C# 本身；xLua 是 Lua 解释器 + 注入桥。这次目标是最小可热配置，选 xLua。**谁都不能替代 AB 热贴图。**
