## 渲染管线
1. 概念：渲染管线是unity将游戏场景中的模型、贴图、光照等数据转换为最终屏幕像素的完整过程，包含几何处理、光栅化、像素着色等关键阶段
    ```
    应用阶段：CPU（准备「画什么」）
        1. 脚本、动画改 Transform
        2. 剔除：视锥体外、被挡住的不画
        3. 排序、合批：能一起画的网格尽量合成一次提交
        4. 发出 Draw Call：一次「用这个 Shader、这批顶去画」

    集合阶段：总线
        顶数据、贴图、常量缓冲交到 GPU

    光栅化阶段：GPU（真的画）
        5. 顶点着色器：模型空间 → 裁剪空间（MVP）
        6. 光栅化：三角形变成像素
        7. 片元着色器：采样贴图、算光、出颜色
        8. 深度 / 模板 / 混合，写入 RenderTexture
        9. URP 后处理（Bloom、你做的 CRT）再画到屏幕
    ```
2. **Draw Call**：CPU 请 GPU 画一批。太多则 CPU 忙着发指令。
3. **SetPass**：换 Shader / 渲染状态，往往比多一次 Draw 更贵。合批是为了少切换。


### 渲染管线分类
1. 内置渲染管线(Build-in render pipeline)
- 特点：unity默认渲染管线，兼容全平台(包括低端设备)，但定制性差，仅支持基础渲染效果
- 适合2D游戏、快速原型开发或旧平台项目
2. 通用渲染管线(URP)
- 优势：
    - 跨平台优化(移动端/PC/VR)
    - 支持Shader Graph可视化编辑
    - 自启动GPU实例化与SRP Batcher
- 适用场景：中小型3D游戏或需要平衡画质与性能的项目
3. 高清渲染管线(HDRP)
- 核心能力：
    - 实时渲染、体积光照、PBR材质
    - 支持高端硬件(如DX12/vulkan)
- 使用场景：3A级游戏、建筑可视化等高清画质需求
4. 自定义渲染管线(SRP)
- 开发自由：通过C#脚本完全控制渲染流程，适合特殊风格(如卡通渲染)或专业领域(如仿真医学)

## MVP

MVP 分别是模型（Model）、观察（View）、投影（Projection）三个矩阵。顶点一般从局部坐标出发，变成世界坐标，再变成观察坐标，再变成裁剪坐标，最后变成屏幕坐标。

1. **M 矩阵**：模型空间 → 世界空间。对顶点做缩放、旋转、平移
2. **V 矩阵**：世界空间 → 观察空间。平移、旋转整个观察空间，使摄像机原点和世界坐标原点重合，坐标轴重合
3. **P 矩阵**：观察空间 → 齐次裁剪空间。对 xyz 分量缩放，用 w 作为范围值。xyz 都落在 w 范围内，这个点才在裁剪空间内

## SRP(unity Scriptable Render Pipeline)
1. 是unity引擎的一种高级渲染管线技术，允许开发者通过C#脚本完全自定义渲染流程，取代传统的固定功能渲染管线。
2. 特点：
- 灵活控制：SRP通过C#脚本控制渲染的每一步，包括剔除、光照计算、材质渲染、后处理等，开发者可以按需优化和实现特殊效果
- 模块化设计：基于RenderPipelineAsset(配置入口)和RenderPipeline(执行渲染逻辑)两个核心类，支持分层设计流程(如分Pass处理阴影、透明物体等)
- 性能优化：支持SRP Batch(减少CPU开销)、动态合批、GPU Instaning等优化技术、尤其适配多平台(移动端/PC/主机)

## 自定义SRP流程
### 一、管线结构基础
1. RenderPipelineAsset：创建管线资产的入口，继承自RenderPipelineAsset并且重写CreatePipeline()方法
2. RenderPipeline类：实现IRenderPipeline接口或继承RenderPipeline，核心逻辑在Render()方法中逐帧渲染

### 二、渲染控制流程
1. ScriptableRenderContext：unity提供的底层渲染上下文，通过Submit()提交指令(如绘制天空盒、集合体)
2. CommandBuffer：封装渲染命令(如清除目标、设置材质属性)需要配合ExecuteCommandBuffer()执行

### 三、Shader和材质兼容
1. Shader编写：需适配SRP的着色器标签(如LightMode = "ForwardBase")或者使用Unlit Shader作为起点
2. 材质兼容性：处理内置管线材质到SRP的迁移，或自定义ShaderGraph

### 四、性能优化
1. 剔除(Culling)：通过Camera.TryGetCullingParameters获取视锥剔除参数，减少不可见的物体渲染
2. 批次合并：利用SRP Bather优化相同材质的物体绘制

## 内置渲染管线迁移
### 一、准备工作
1. 项目备份：使用版本控制(Git/SVN)或者手动被封文件夹，避免不可逆的材质或者着色器损坏
2. 版本兼容性检查：URP/HDRP需要unity 2019.3或更高版本，建议使用unity 2021 LTS或者更高版本以获取稳定支持
3. 安装对应的package：通过Window > Package Manager安装Unity RP(URP)或High Definition RP(HDRP)

### 二、具体步骤
1. 创建URP配置资产
- 右键项目窗口：Create > Rendering > Unity Render Pipeline > Pipeline Asset生成URP主配置和渲染器资产
2. 切换默认渲染管线
- 打开Edit > Project Settings > Graphics，将Scriptable Render Pipeline Settings字段指向刚刚创建的URP资产
3. 材质转换和着色器转换
- 自动转换：使用Edit > Render Pipeline > Universal Render Pipeline > Upgrade Project Materials批量升级内置材质到URP兼容版本
- 手动修复：自定义着色器重写HLSL语言，替换CGPROGRAM为HLSLPROGRAM并且更新头文件(如UnityCG.cginc改为URP的Core.hlsl)
4. 光照和阴影调整
- URP的光照模型和内置管线不同，需要重新烘培光照贴图或调整光源参数(如光强和阴影分辨率)

## 摄像机
1. camera是unity用于渲染场景的组件
- Clear Flags：决定如何清除屏幕(Skybox/Solid Color/Depth Only/Don't Clear)
- Culling Mask：控制哪些图层(Layer)会被渲染
2. 如何实现分屏或多摄像机渲染
- 通过调整Viewport Rect属性来划分屏幕区域
```Csharp
    camera1.rect = new Rect(0, 0, 0.5f, 1); // left camera part
    camera1.rect = new Rect(0.5f, 0, 0.5f, 1); // right camera part
```
3. Camera的Clipping Planes(裁剪平面)
- Near：最近渲染距离，过小会导致近处物体裁剪(如UI消失)
- Far：最远渲染距离，过大会增加渲染负担
- 注意：地形渲染需要确保Far足够大，但要避免包含无关物体
4. 视野
- `fieldOfView`：透视相机的垂直视野角，单位是度。角度越大，看到的范围越宽，物体显得越小
- `orthographic`：勾上后成为正交相机
- `orthographicSize`：正交相机画面一半的高度。大小和距离无关，物体远近不会变大变小
- 正交相机没有近大远小，同样尺寸的物体在远处和近处一样大。适合 2D 平台、俯视战棋、卡牌桌面，以及需要尺寸对照的示意画面
- 透视相机有近大远小，用来表现纵深。适合第一人称、第三人称、赛车和开放世界
5. 实现摄像机跟随角色平滑移动
```CSharp
void LateUpdate() {
    transform.position = Vector3.Lerp(transform.position, target.position + offset, 0.1f);
}
```
- 或者使用Cinemachine插件实现复杂的跟随逻辑(如轨迹、阻尼等)

## Mesh

Mesh 是网格数据的脚本接口。它用数组描述形状：

- **顶点 vertices**：三维空间中的点，类型是 `Vector3[]`
- **三角形 triangles**：每 3 个顶点索引围成一个面，类型是 `int[]`
- **UV uv**：顶点在贴图上的坐标，通常在 `(0, 0)` 到 `(1, 1)` 之间

立方体、平面都可以用少量三角形精确表示；曲面只能用很多小三角形逼近。

生成网格的固定步骤：

```csharp
mMesh.Clear();

mMesh.vertices = _vertices;
mMesh.uv = _uvs;
mMesh.triangles = _triangles;

mMesh.RecalculateNormals();
mMeshFilter.mesh = mMesh;
```

- `Clear()`：清空旧顶点、三角形、UV、法线
- `vertices` / `triangles`：写入几何
- `uv`：写入贴图坐标，后面 Shader 靠它采样
- `RecalculateNormals()`：按三角形绕序自动算法线

### UV

纹理空间只有两个轴，叫做 U 和 V。网格上的每个顶点都带一个 UV。GPU 在三角形内部插值 UV，再去贴图上取样颜色。

- 地板：整张网格 UV 从 `(0, 0)` 铺到 `(1, 1)`
- 立方体：每个面单独 4 个顶点，每个面自己铺一张 0~1 的 UV，避免相邻面抢同一套坐标

### MeshFilter

MeshFilter 只保存要画的 Mesh，自己不负责上屏。

- `sharedMesh`：引用一份共享网格。多个物体可以指向同一个 Cube、同一个导入模型
- `mesh`：读取时会复制出一份网格；写入时表示这份网格归当前物体使用

### MeshRenderer

MeshFilter 和 MeshRenderer 成对出现。Filter 提供形状，Renderer 提供材质、阴影和渲染层。只有 Filter 没有 Renderer 时，场景里看不见网格。

- `sharedMaterial`：直接使用那一份材质。改它的颜色会影响到所有引用者
- `material`：第一次访问时复制一份运行时材质，之后只改这个物体
- `sharedMaterials` / `materials`：多材质槽版本，规则与上面两个相同
- `shadowCastingMode` / `receiveShadows`：是否投射、接收阴影
- `SetPropertyBlock` / `GetPropertyBlock`：按物体覆盖 Shader 属性，不复制材质
- `enabled`：关闭后停止渲染，网格数据仍在

`material.color` 写的是 Shader 属性 `_Color`。

```csharp
mMeshRenderer.sharedMaterial = mSourceMaterial;
mMeshRenderer.material.color = _color;
```

先指定共享材质，再访问 `material`。第二次赋值会作用在已经复制出来的那份材质上。

### MaterialPropertyBlock

每个物体都访问 `material` 时，Unity 会各复制一份材质，批次被拆开，内存也上去。`MaterialPropertyBlock` 把覆盖值存在 Renderer 上，材质资源仍然只有一份。

```csharp
mSharedMaterial = new Material(mSourceMaterial);
mSharedMaterial.enableInstancing = true;
_meshRenderer.sharedMaterial = mSharedMaterial;

_propertyBlock.Clear();
_propertyBlock.SetColor(kColorId, _data.Color);
_meshRenderer.SetPropertyBlock(_propertyBlock);
```

这里的 `new Material` 只发生一次，随后所有立方体都走 `sharedMaterial`。属性名用 `Shader.PropertyToID("_Color")` 缓存。

Shader 里要把这个颜色声明成实例属性，GPU Instancing 才能带着各自的颜色合批。材质面板上的 Enable GPU Instancing 对应 `material.enableInstancing`。同时满足这几条才会实例化合批：

- 同一个 Mesh
- 同一份 Material，且 `enableInstancing == true`
- Shader 有 `#pragma multi_compile_instancing`
- 每个物体不一样的参数来自 MaterialPropertyBlock，并且在 Shader 里是 instanced property

`MaterialPropertyBlock` 会使该 Renderer 不走 SRP Batcher。需要按物体变色、又要合批时，用 GPU Instancing。

### GPU Instancing 与 Static Batching

两条路径都用来减少 Draw Call，适用情况不同。

**GPU Instancing**

运行时把相同网格、相同材质的物体打成一次绘制。物体仍然可以各自移动。材质打开 `enableInstancing`，Shader 声明实例属性后，颜色、金属度这类差异放进 `MaterialPropertyBlock`。

**Static Batching**

把勾选了 Batching Static、且共用同一材质的静止物体，在构建时合并成大网格。合并之后这些物体不能再移动，也不能再靠 MaterialPropertyBlock 各自变色。关卡里不动的桌子、墙用 Static Batching。

### SkinnedMeshRenderer

角色、布料这类会随骨骼变形的网格用 `SkinnedMeshRenderer`，不用普通 `MeshRenderer`。

- `sharedMesh`：蒙皮网格，顶点带骨骼权重
- `bones`：影响蒙皮的骨骼 Transform 数组
- `rootBone`：根骨骼，用于计算包围盒
- `quality`：骨骼混合品质（SkinQuality）
- `updateWhenOffscreen`：离开屏幕后是否继续计算蒙皮
- `SetBlendShapeWeight` / `GetBlendShapeWeight`：读写 BlendShape 权重
- `BakeMesh`：把当前姿势烘焙成普通 Mesh

### SpriteRenderer 与 LineRenderer

**SpriteRenderer** 用于画 2D 精灵，不需要 MeshFilter。

- `sprite`：要画的精灵
- `color`：顶点色，会乘到精灵颜色上
- `flipX` / `flipY`：水平或垂直翻转
- `drawMode` / `size`：Simple、Sliced、Tiled 以及平铺尺寸
- `sortingLayerID` / `sortingOrder`：2D 排序

**LineRenderer** 按一组点画线段或带状网格。

- `positionCount`：点的数量
- `SetPosition` / `SetPositions`：写入每个点
- `useWorldSpace`：点坐标使用世界空间还是局部空间
- `startWidth` / `endWidth` / `widthCurve`：线宽
- `startColor` / `endColor` / `colorGradient`：沿线的颜色
- `loop`：首尾相连
- `material`：线段使用的材质
- `numCornerVertices` / `numCapVertices`：拐角和端点的圆滑细分

## 材质与着色器

### 数据流

```
Shader（算法）
  └─ Material（算法 + 具体参数：颜色、亮度、两张贴图、混合权重）
        └─ MeshRenderer.material（把这份参数应用到 MeshFilter 里的网格）
```

- **Shader**：告诉 GPU 怎么把顶点变成像素。它声明属性名，例如 `_MainTex`、`_Brightness`
- **Material**：Shader 的一份填好的参数表。同一 Shader 可以做出很多不同外观的材质
- **Texture**：贴图资源本身，不直接画到物体上，必须先交给 Material
- **MeshRenderer**：拿着 Material 去画 MeshFilter 里的 Mesh。采样时用的是网格 UV

改 Shader 代码会改变所有使用它的材质；改 Material 参数只影响这一份材质。

### Unlit Shader 和 Surface Shader

**Unlit Shader**：自己写顶点着色器和片元着色器，不计算场景光照。结构是：

```
Shader "名字"
{
    Properties { ... }          // 暴露给 Material 面板的参数
    SubShader
    {
        Pass
        {
            顶点着色器 Vert     // 物体坐标 -> 裁剪坐标，并传递 UV
            片元着色器 Frag     // 用 UV 采样贴图，输出最终颜色
        }
    }
}
```

**Surface Shader**：Unity 帮你生成光照代码，你只填表面属性。

```hlsl
Shader "Learn/SimpleSurface"
{
    Properties
    {
        _MainTex ("Albedo", 2D) = "white" {}
        _Color ("Color", Color) = (1, 1, 1, 1)
    }
    SubShader
    {
        CGPROGRAM
        #pragma surface surf Lambert
        sampler2D _MainTex;
        fixed4 _Color;

        struct Input
        {
            float2 uv_MainTex;
        };

        void surf(Input IN, inout SurfaceOutput o)
        {
            fixed4 _c = tex2D(_MainTex, IN.uv_MainTex) * _Color;
            o.Albedo = _c.rgb;
            o.Alpha = _c.a;
        }
        ENDCG
    }
}
```

### UV 映射与贴图采样

1. Mesh 顶点带 `uv`
2. 顶点着色器做 `TRANSFORM_TEX(uv, _MainTex)`，加上材质上的 Tiling / Offset
3. 光栅化时，三角形内部每个像素得到插值后的 UV
4. 片元着色器用这个 UV 采样：

```hlsl
float4 _texA = SAMPLE_TEXTURE2D(_MainTex, sampler_MainTex, _input.uvA);
float4 _texB = SAMPLE_TEXTURE2D(_SecondTex, sampler_SecondTex, _input.uvB);
float4 _blended = lerp(_texA, _texB, saturate(_Blend));
return _blended * _Color * _Brightness;
```

- `lerp(A, B, t)`：`t = 0` 全是贴图 A，`t = 1` 全是贴图 B
- `_Color * _Brightness`：材质控制色调与亮度

### 用代码设置纹理

`SetTexture` 的第一个参数必须和 Shader 里的属性名一致。用 `Shader.PropertyToID` 把属性名换成整数，避免每帧查字符串。

```csharp
private static readonly int kMainTexId = Shader.PropertyToID("_MainTex");
private static readonly int kSecondTexId = Shader.PropertyToID("_SecondTex");

mRuntimeMaterial.SetTexture(kMainTexId, mTextureA);
mRuntimeMaterial.SetTexture(kSecondTexId, mTextureB);
mRuntimeMaterial.SetColor(kColorId, mTintColor);
mRuntimeMaterial.SetFloat(kBrightnessId, mBrightness);
mRuntimeMaterial.SetFloat(kBlendId, mBlend);
```

用 `renderer.material`（运行时副本），不要用 `sharedMaterial`，否则会改到工程里的材质资源。

## 面试题
### 1. 什么是渲染管线？ Unity中哪些主要类型？
- 渲染管线将3D场景数据转换成2D屏幕像素的流程，包括几何处理、光栅化、着色器等阶段
- 包含以下类型：内置管线、URP、HDRP、自定义SRP

### 2. 如何在SRP中实现后处理效果(如Bloom)
- 创建RenderFeature和RenderPass
- 使用CommandBuffer.Blit在临时RT间传递图像数据
- 编写Shader实现高斯模糊和亮度阈值过滤

### 3. URP中如何减少Overdraw
- 分层渲染：先渲染不透明物体(由近到远)再渲染透明物体(由远到近)
- Early-Z：通过深度Pass提前剔除不可见像素   

### 4. 光照和阴影优化的常见方式
- 阴影：使用级联(CSM)、降低阴影分辨率
- 光照：烘焙静态光照(lightMapping)、动态光源数量限制

### 5. 如何调试自定SRP的性能问题
1. 关键指标：Drawcall数量、RT切换次数、Shader复杂度
2. 工具：Frame Debugger\Profiler
